# Memory/context receipt observability

Local receipts are captured at `captureRuntimePromptManifest` and linked in the manifest as `contextReceipt`. They are **assembled provider-bound attempts**, never evidence that a provider accepted the request or returned a successful response. Each attempt has a unique manifest ID. Latest textual provider-bound user input supplies a raw SHA-256 join key; normal chat supplies its gateway turn ID and original request separately; callers that do not supply them are explicitly marked unavailable. Automatic/atomic recall provenance, ranking, suppression and answer efficacy are explicitly unavailable, not inferred from absence.

Storage resolves runtime configuration's workspace, under `audit/context-receipts`. Default enabled, seven-day age retention, maximum 256 receipt files, 49,152,000-byte worst-case disk cap (256 × 192,000), 192,000 bytes per file and 48,000 stored text characters shared across user input and sections. Pruning maintenance runs at most once per minute unless the count limit is reached; API reads honor configured age. Raw original, full redacted and stored-text SHA-256 hashes are separate. Redaction/truncation/offsets and exact-content duplicates carry explicit flags and canonical references. Text is a bounded privacy-scrubbed representation, **not exact complete raw context**. Hashes are identity evidence, not encryption; local receipts can still contain personal noncredential text.

Recognized line delimiters include USER/SOUL/MEMORY, AUTO_RECALL, ATOMIC_MEMORY, extended BRAIN_ACTIVE_CONTEXT and TODAY_NOTES, SKILLS/MATCHING_SKILLS and memory search/retrieved/reference diagnostics. Sections are delimited by the next uppercase bracket marker or USER/SOUL/MEMORY Markdown heading. Unlabeled context and user-message injected context remain unclassified. No assistant messages, tool payloads/schema, structured reasoning or media are retained. Credential scrubbing follows existing audit materializer patterns with stricter JSON/key/media/private-key protection; it is not a guarantee against all natural-language secrets.

Authenticated shared desktop/mobile backend (existing audit-log router mounted behind gateway auth and account access):
- `GET /api/context-receipts?days=7&limit=20&sessionId=...&detail=true` (days 1–30, limit 1–100).
- `GET /api/context-receipts?id=rpm_...` returns a bounded detail record; invalid IDs cannot traverse paths.
- `POST /api/context-receipts/settings` with `{enabled:false}`, `{retentionDays:3}` or `{reset:true}` reversibly disables, configures retention or deletes receipts. Disabling does not delete; resetting does not implicitly disable.

No UI or agent tool was added in this lane. Coordinating agent owns agent-tool integration via audit-ops. Exports available: `readContextReceipts({id?,sessionId?,days?,limit?,detail?}, root?)`, `contextReceiptSettings(root?)`, `configureContextReceipts({enabled?,retentionDays?,reset?}, root?)`. Optional root is for tests/internal trusted callers only; API never takes an arbitrary root. Provider coverage is only actual manifest capture callers; provider-specific downstream transformations and response success are not instrumented here. No remote provider coverage claim is made. Tests: `npx tsx src/runtime/context-receipt.regression.ts`; final project typecheck/build owned by coordinating agent.

Gateway integration: callers can pass ephemeral `context.gatewayTurnId` and `context.originalUserRequest`. Receipts then retain redacted original `userInput` separately from actual latest `providerBoundUserInput`; input is never serialized as raw manifest context. Caller integration is coordinator-owned, so missing original/turn IDs remain explicitly unavailable.

Native `prometheus_audit_ops(action:"context_receipts", detail:true)` provides agent-readable receipts; `context_receipt_settings` exposes current retention/enabled state. Normal chat supplies gatewayTurnId and originalUserRequest per model round, so the redacted original request is separated from the latest transformed provider-bound user message and joins skill-learning evidence. Records are attempts, not proof of successful responses.

Regression coverage also checks the actual atomic formatter delimiter `[MEMORY_REFERENCE]`. Downstream provider-specific prompt transformations and internal retries remain outside this receipt boundary; full retrieval candidate/ranking/suppression provenance needs a separate retrieval-event producer.
