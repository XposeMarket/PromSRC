# Web UI performance program — PR 3 production module pipeline

Date: 2026-08-22
Source baseline: `f19b299b82dfc2feb10ea1b6a4a7a02f81a46da9`
Stack base: PR #191 / `50ea6d391db1f991cd7d93910e1175c6910a9d04`
Branch: `perf/web-ui-production-modules`

## Outcome

Public and Electron-distribution builds now use a deterministic, dual-document
ES module pipeline. The gateway's source-development path remains native browser
modules under `web-ui/`; only `generated/public-web-ui/` receives minified,
content-addressed entries, feature chunks, CSS, media, and extracted classic
scripts. No framework or client runtime was introduced.

esbuild is used instead of adding Vite because Prometheus already depends on its
compiler, does not need a dev server, and has a purpose-built public mirror and
Electron packaging path. It is now a direct pinned development dependency. The
pipeline uses static ESM discovery, tree shaking, ESM splitting, and feature
names derived from explicit dynamic imports. Source maps and arbitrary vendor
splits are not shipped.

## Entries and chunk ownership

| Surface | Source entry | Production behavior |
| --- | --- | --- |
| Desktop document | `src/desktop-entry.js` | auth and tiny boot owner; desktop state/app modules remain dynamic |
| Mobile document | `src/mobile/mobile-entry.js` | PWA owner and immediate router boot closure |
| Desktop styles | `styles/desktop-entry.css` | minified current desktop layers plus local font declarations |
| Mobile styles | `styles/mobile-entry.css` | minified focused mobile stylesheet |
| Settings | `pages/SettingsPage.js` | addressable lazy entry for the synchronous shell shim; excluded from boot |
| Desktop pages | explicit `PAGE_MODULE_LOADERS` in `app.js` | named Chat, Tasks, Schedule, Teams, Subagents, Proposals, Audit, Memory, Hub, and Connections chunks |
| Mobile routes | explicit owner loaders in `mobile-router.js` | named Pair, Gateway, Chat/Voice, Schedule, Teams, Tasks, Settings, Hub, Proposals, Creative, and Subagent chunks |
| Legacy classic scripts | document-order extraction | syntax/whitespace minified, content hashed, stable global identifiers preserved for inline DOM handlers |

The prior `import(variable)` desktop page router was replaced with explicit
loader functions. This is a correctness requirement: a bundler cannot discover
runtime strings, and retaining them would point hashed chunks back to raw source.
The source browser still performs the same native imports.

`asset-manifest.json` is the authority for document entries, every output's
bytes/gzip/digest/imports, source-to-feature output mappings, and static boot
closures. Its build ID covers all Web UI sources, the compiler/package inputs,
the builder itself, and generated local font declarations.

## Before and after

Measurements use level-9 gzip over the exact generated bytes plus a Chromium
request ledger with service workers blocked. The route ledger loads and evaluates
real modules rather than estimating from source text.

| Surface | PR 2 raw-module gzip | Production gzip | Change |
| --- | ---: | ---: | ---: |
| Mobile Pair JS | 148,678 | 96,866 | -34.8% |
| Mobile Schedule JS | 145,119 | 94,361 | -35.0% |
| Mobile Chat JS | 636,362 | 436,828 | -31.4% |
| Mobile requested CSS | 104,697 | 76,252 | -27.2% |
| Desktop HTML | 108,121 | 56,289 | -47.9% |

The content-addressed mobile shell/parser closure is 87,698 gzip JS and 76,252
gzip CSS. It meets both initial shell targets. Pair and Schedule also remain
under 100 KB gzip JS after their requested route owners evaluate. Chat is a
recorded staged miss against the 250 KB goal; its remaining 436.8 KB is dominated
by the Chat/Voice runtime and optional render ownership addressed in PRs 4 and 6.

The desktop parser/boot closure is 49,249 gzip JS and 96,461 gzip CSS. Its source
HTML drops from 566,872 to 340,964 raw bytes and from 108,121 to 56,289 gzip by
moving executable classic bodies into independently cached hashed assets.

## Cache, service worker, and gateway

`/build/*` receives `public, max-age=31536000, immutable`; HTML, the manifest,
the service worker, and stable `/static/*` mirrors still revalidate. This avoids
both stale stable filenames and redundant revalidation for content hashes.

The source service worker retains a raw-module fallback precache. The production
builder injects exactly one manifest-derived mobile boot closure and a source
digest cache namespace. It never activates raw and built precache identities at
the same time. A new source digest changes the service-worker body and cache key;
activation removes preceding Prometheus cache versions. Navigation, API/SSE/WS
bypass, notifications, badge state, install/update, offline shell, and cache
purge behavior are preserved.

## Compatibility, packaging, and rollback

- `npm run dev` and a non-public gateway keep serving `web-ui/` native modules.
- `sync:web-ui` builds and verifies raw mirrors and hashed production output in
  one deterministic operation.
- Public Electron builders already include `generated/public-web-ui/**/*` and
  exclude source maps. The release verifier now opens the asset manifest inside
  `app.asar` and requires every referenced hash.
- The gateway MIME table already supports every emitted type; source assets and
  absolute `/assets` and `/vendor` contracts are preserved.
- The desktop production browser smoke loads the real generated document,
  resolves the boot promise, clears auth gating, and observes no missing hashed
  asset or module evaluation error.
- Rollback is a stack/deploy rollback. There is no persistent storage or API
  schema migration. PR 2's `index.html` mobile fallback still works because
  `desktop-entry.js` retains a mobile-only recovery branch.

## Risks and deliberate deferrals

- Chat still contains a 1.3 MB minified feature output plus a large shared chunk.
  PRs 4 and 6 move runtime state and optional Creative/Browser/rich renderers
  before attempting a finer split.
- CSS is minified and below target, but its source ownership remains broad.
  Decomposition stays behind runtime/view ownership to avoid selector-order
  regressions and line-count-only work.
- The legacy classic program is cached outside HTML but not yet a clean module
  owner. PR 6 can retire it incrementally after feature behavior has moved.
- The gateway still becomes the Electron navigation authority. Paint-before-
  readiness remains an evidence-driven PR 6 decision rather than being coupled
  to this asset migration.
