# Document Coauthoring

Use for a substantial document whose quality depends on context, structure, decisions, and how a fresh reader will understand it. Work in three deliberate stages.

## 1. Context gathering

Identify document type, audience, decision or outcome, desired reader action, format/template, deadline, constraints, stakeholders, alternatives, risks, and source material. Let the user provide an unstructured dump. Track known facts, assumptions, missing context, and questions. Read supplied files or connected sources only when authorized and preserve provenance.

## 2. Refinement and structure

Propose a lean outline that fits the document type. Start with the section carrying the most uncertainty, usually the problem, decision, or technical approach. For each section, clarify intent, draft from verified context, remove redundancy, and resolve contradictions. Use precise terms, active voice, explicit owners and decisions, and distinguish facts, assumptions, options, and open questions. Keep placeholders visible rather than inventing details.

For specs and RFCs, cover problem, goals/non-goals, current state, proposed design, alternatives, interfaces, failure modes, rollout, migration, observability, security, testing, and decision status when relevant. For proposals and briefs, cover audience, need, approach, proof, cost/tradeoffs, and next action.

## 3. Reader verification

Before finalizing, reread the whole document for flow, unexplained terms, duplicated claims, missing decisions, unsupported certainty, and generic filler. Predict realistic reader questions. Test the document with a fresh-context reviewer or a deliberate cold read, then patch only demonstrated confusion. Confirm links, tables, headings, examples, and references. If a formal artifact is requested, use the appropriate document skill and reopen/verify the result.

## Output contract

Return the working outline, context gaps, section drafts, decisions and open questions, reader-test findings, final verification, and exact artifact path when applicable. Do not present a polished document as decision-ready if key context remains unresolved.
