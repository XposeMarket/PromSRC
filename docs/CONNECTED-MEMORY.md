# Connected memory implementation

## Stage A: retention foundation (PR822, deployed)

This is the first independently reviewable stage of the locked connected-memory plan, not a usable connected library yet. There are **no UI changes** and automatic library capture is compile-time OFF (`AUTOMATIC_REFERENCE_CAPTURE_READY`). Do not enable it before search/open, access rules, exclusion/deletion controls and the desktop/mobile Memory controls ship together. No user material is bulk imported; no extra model or paid analysis calls are introduced.

### Ownership and persistence
`ResourceStore` remains authoritative for resources, immutable versions and snapshot bytes. `resources/references.sqlite` owns saved reference intent/provenance and the only new `version_pins` table; it is not a generated search cache. Existing bundled better-sqlite3 is lazy-loaded. The service is gateway-internal; it is not a public permission boundary. Workspace scope is not a user/team grant or filesystem sandbox. B/C must implement caller/grant enforcement before exposure.

A synchronous save validates evidence, commits pending pins first, fsyncs snapshots, flushes/fsyncs the resource registry, then atomically creates the reference and promotes pins. Startup recovery completes only operations whose registry versions and snapshots are durable. Unknown/missing pending evidence remains pinned, never expired by age. Repeated operation IDs reuse the existing completed capture; conflicting main bindings are rejected.

ResourceStore cleanup reads pins on every flush across instances. Unreadable/corrupt/unavailable reference metadata suppresses pruning, not ordinary attachment writes. A `references.required` marker prevents silently treating a lost database as an empty library. Restore database plus its WAL consistently; do not remove the marker to force cleanup.

The metadata writer holds an exclusive `references.lock` with random token, process identity and hostname. Other processes read an existing DB but writes fail visibly. Dead-process recovery requires same host and a provably nonexistent process; a live/reused PID, permission error, invalid identity or orphaned recovery lock is conservative read-only. No age-based lock stealing. Operator recovery requires stopping all consumers and backing up the resources directory before moving an abandoned lock. A recovery-lock crash may require that explicit procedure. This guards the new metadata writer, not all legacy filesystem tools.

### Media evidence
Each `analyze_video` run gets a UUID child folder, including when `output_dir` is supplied (it now names the parent). Retained run folders are never auto-deleted: frames, contact sheets and audio accumulate per call, so disk use grows until B/C storage controls (UUID-owned run pruning with pin awareness) ship. `extracted.json` preserves produced frames/contact sheets/audio hashes, known frame timestamps, source hash, available transcript and requested focus before the optional report model runs. `complete.json` adds the returned report. Direct observation never fabricates an analysis report. Coverage is explicitly sampled frames, not continuous playback. Analyzer paths must stay within this run. No new dependency assumptions; existing extraction/transcription availability remains unchanged.

Manifests describe existing output, not a hidden default reference archive. Future gated capture snapshots the source and one archived manifest resource per run. Frame/audio blobs are copied to managed `resources/content/analysis/<operation-hash>/` without a resource registry row per frame; they survive temporary workspace output removal. Originals and the run version are pinned. A source video and total derivative bundle each have a 100 MiB cap, and a run has at most 160 files. Oversize capture fails explicitly without deleting outputs or selecting a paid provider. Incomplete archive copies are retained, not advertised as complete or silently deleted; B/C deletion/export/storage accounting must cover them.

### Ingress and limits
Dormant adapters cover common chat attachment registration and Memory-note attachments using existing resource IDs, plus completed video manifests. No endpoint, memory-tool action, team sharing, legacy import or auto-discovery is added in A. No semantic OCR or visual-search claim. Channel-specific transport and project continuity remain future acceptance requirements.

### Verification
`node scripts/test-connected-memory-foundation.mjs` exercises real SQLite, registry snapshots, 26-version retention, missing DB fail-closed behavior, second process writer rejection, workspace read isolation, restart/pending recovery, idempotency, immutable manifests, traversal refusal and archived original/frames. All data is temporary synthetic data.
`node scripts/test-media-analysis-previews.mjs` exercises the real video function with external extractor/provider fixtures and existing preview paths; its custom loader resolves imports relative to each source module. It checks repeated run manifests, honest transcript/analysis absence, direct vs report behavior and desktop/mobile preview renderers. This is not a physical-phone or real remote-model test.

### Remaining approved work
B+C: typed memory search/open, actual provider image delivery, exclusions/correction/permissions, desktop/mobile Memory controls, owner switches, storage/export/delete and backup UX. D: explicitly shared collections and exact-version durable team/verifier handoffs. E: project fresh-chat continuity and supported channel ingress. A alone must never be reported as the finished feature.

## Stages B+C: personal library (successor PR; not deployed)

The existing desktop and mobile Memory page gains a References tab, not a separate application. Owners can save pictures/documents/notes/links with a purpose, search, inspect original images or sampled saved video frames, correct title/interpretation/purpose/notes, mark guidance as saved/suggested/confirmed, link references and inspect backlinks, exclude/restore, delete, and download a portable ZIP containing original bytes plus context. The storage indicator is an approximate installation-managed ResourceStore total (cached 60 seconds), not a claim that every byte belongs to this library. Deleted references unpin managed evidence; external originals, source chats, analysis run folders, and previously delivered copies are unchanged.

`memory(action:"search"|"recall")` adds bounded reference matches. `memory(action:"open", reference_id, version_id?, offset?, limit?)` returns saved content and stable provenance. Actual vision observation is separately resolved from trusted storage into the next model request. Images are not accepted from paths/base64 supplied in tool results. Saved video analyses reopen up to 6 frames by default (maximum 12, with offsets/timestamps and sampled-coverage labels); no redownload, provider analysis, or transcription is triggered. Nonvision routes are explicitly told the images were not viewed. Authenticated owner preview/export routes share the gateway/account guards. Cross-workspace and version mismatches, corrupt/missing bytes, background/team/agent callers and model opens of excluded references are refused. This is an application retrieval boundary, not a filesystem sandbox.

Capture and relevant-reference suggestions are independent, default-off owner switches. Enabling capture is forward-looking: ordinary registered chat attachments and notes/attachments saved through Memory, plus completed video analysis with a trusted personal session, can be saved. Existing history is not bulk imported. Pointer recall is bounded to three relevant text pointers; images still require explicit opening. Channels and project/assignment-specific adoption remain Stage E work.

“Don’t use as reference” excludes the entry from model discovery/open. “Forget source chat from memory” additionally suppresses its ENTIRE source session from memory-index/recall retrieval, including future rebuilds; it does not erase raw transcript files, independently written memory facts, or copies already sent to a model. Restoring reference use reverses that entry’s suppression. Deleting a source chat retains references by default; the desktop/mobile confirmation offers an explicit also-delete choice. If the library is read-only, that chosen mutation fails before deleting the chat. Teams have no implicit access: sharing controls are intentionally unavailable until Stage D.

### B+C evidence and boundaries
Regression suites: `test-connected-memory-foundation.mjs`, `test-media-analysis-previews.mjs`, `test-connected-memory-library.mjs`, `test-connected-memory-vision.mjs`, `test-connected-memory-controls.mjs`, `test-connected-memory-retrieval.mjs`. Vision fixtures inspect both Anthropic and OpenAI serialized request bodies. The real isolated Haiku fresh-chat probe searched and reopened a saved image and accurately described its geometric shapes/colors and owner purpose. This is not a live OpenAI-provider or physical-phone claim. Retrieval fixtures exercise real lexical search/auto-recall, forget, rebuild and undo; semantic provider search is not exercised. Stage A PR822 is deployed; B+C remains pending review/merge. D explicit team grants/exact-version handoffs and E project/channel continuity remain approved but unimplemented.

Review R1 hardening: personal model opens/search/pointers require trusted interactive owner context and reject noninteractive execution modes even if a webhook selects an existing owner session key. Webhook, scheduled and external-channel session families are denied; channel adoption is Stage E, not implicitly enabled. Owner HTTP routes remain authenticated independently. Ordinary upload capture now has one canonical ingress with explicit UI-origin preflight, consistent filename/type normalization and per-item exclusion skips; no duplicate model-loop capture. Desktop source-chat deletion uses explicit Cancel / delete chat keep references / delete chat and references choices. A partial reference cleanup truthfully reports the chat deletion and removed count plus warning, rather than falsely returning generic deletion failure.

R1 turn provenance: ordinary UI/terminal turns receive an explicit server-side personal-reference permission carried by the current async trace. Timer/goal/watch/subagent/supervision and external-channel turns do not. Webhooks cannot acquire it by choosing an owner session ID. Nested same-session traces reuse permission only when both execution mode and permission match; otherwise a fresh child context is created. Internal compaction/flush turns do not automatically gain original-evidence access. The normal owner turn still reopens archived originals with no additional media analysis.

Asynchronous session wakes (including thread-completion callbacks) carry an explicit `system` origin, rather than falling back to an interactive web owner. They can notify the owner but cannot access personal references. The owner's next ordinary message retains normal access.

## Stage D: explicit team reuse
The owner can share a saved reference or a collection with an existing team in the shared desktop/mobile Memory → References controls. Ordinary grants are optional; explicitly checking and confirming “Required for every task in this team” creates team-wide guidance. Revoking removes subsequent access and the requirement but cannot unsend evidence. Adding an item to a shared collection displays its team audience and requires confirmation. Capture/recall defaults do not change.

Team entrypoints install a per-turn async scope. IDs in model arguments, actor maps and session prefixes do not grant library access. Team search filters authorized IDs before titles/snippets/counts; open and image delivery recheck current grants, including after image normalization. Private main-memory discovery tools remain unavailable to this scope. Direct files/terminal permissions are a separate boundary; this is not a filesystem sandbox.

`memory select`/`unselect` freezes explicitly shared reference/collection members in the current team task or session. `memory open` also records the exact evidence actually opened. Selections include purpose, resource/version and grant IDs. Model selection cannot create grants or mandatory guidance. Dispatcher snapshots selections before queue admission and adds explicitly owner-required applicable team-wide references independently of similarity retrieval. Builders, resumed/rerun tasks and verifiers retain the same selections; a new collection member never silently changes an existing task. Owner guidance requires revocation to remove.

Canonical task selections live in task JSON; taskless manager/member selections live in the workspace-scoped references database. The latter are session state, not a duplicate task selection authority. Task writes pin exact versions and dependent original-video versions before persistence. Stale runner/checkpoint snapshots cannot erase later selections. Terminal persistence releases only its own task lease after verification; paused/queued runs retain leases. Revocation blocks access but cannot prevent recording a task’s failure/pause. Team/subagent context-reference loaders preserve typed bindings and pointer-only records. Newest versions are not substituted automatically.

Stages E (project/channel adoption) and the graph redesign are not part of D. Tests use isolated synthetic teams, stores and provider serialization; no real team reference shares are performed during verification.

### Known limitation: Windows terminal-save durability (accepted)
When a team task that held reference selections reaches a terminal state, `saveTask` writes the task file with a complete write + `fsync`, renames it into place, flushes the directory, and only then releases the task's version pins. Real I/O errors propagate and the pins are kept. Windows cannot `fsync` a directory handle, so on Windows the rename itself is not separately proven durable before the pin release, which is its own SQLite commit. If power or the OS fails in that instant, the task can come back non-terminal with its pins already released. Versions older than the 25-version window may then be pruned. This affects evidence availability only. Access is unaffected because grants are always checked live. The owner accepted this as a documented platform limitation on 2026-11-07 (PR #840, review R3).
