# System-wide plugin audit

Date: 2026-11-08 · baseline `82b547a68254d950cb801c72ddb39bf48f0e1218`

Source classification only; no real auth, config reads, runtime initialization, network verification, plugin execution or source changes. Main owns implementation/build; merge, deployment and real account auth remain separate.

## Findings (13)

1. Complete bounded bundled inventory: **49 manifests: 16 native connectors, 9 MCP presets, 24 providers; 48 distinct raw IDs**. All declare enabledByDefault=true; actual enabled/auth state was not read.
2. One known installed manifest was found by metadata-only inspection: legacy **integration:github**. Native connector:github and mcp_preset:github already collide by raw ID. Use kind/origin-qualified trusted identity; do not merge their credentials or attempts.
3. Shared discovery excludes known identities without connection metadata unless API-key setup fields exist. **11 manifests declare connection strategies; 22 use API-key derivation; 16 are excluded.** Substring alias matching can map X to Nous/hermes proxy. Exact installed identity must precede eligibility/fuzzy matching.
4. Nine native OAuth bridges have real read-only verifier implementations (listed per row). X, Instagram, LinkedIn and TikTok have existing service-specific runtimes/read methods but no shared connection declarations/bridges; this is wiring debt, not permission to invent auth support.
5. X needs its existing typed OAuth2 app protected branch: generic /api/protected-plugins/request explicitly rejects x. Pin OAuth client fields, callback/scopes, owner/storage proof and attempt correlation; browser login is not official API verification.
6. API-key derivation covers 18 providers, Stripe/Vercel and Brave/GitHub MCP presets. Generic runtime verifier deliberately returns **stored, not verified**. Preserve that truth; a source-supported setup path is not authenticated/healthy.
7. Providers have exceptions: Anthropic setup-token, Codex OAuth, xAI API-key-or-OAuth, three local model hosts, and Nous external Hermes proxy. Nous declares local-resource but supplies endpoint/prerequisite, while generic local-resource expects a path and is not built-in registered in the inspected runtime. Reconcile actual contribution before treating it supported.
8. MCP presets need host/process/platform prerequisites. Filesystem hardcodes C:\Users; SQLite uses a Windows placeholder; Postgres DSN can contain a password despite authType none. Windows/mac-messages require uvx and matching OS. Protect DSNs and request least-privilege real resource selections.
9. Hosted Robinhood declares desktop onboarding and read-only exposure. Preserve existing OAuth popup/callback routes and consent. MCP read-tool name heuristics/discovery are not a substitute for pinned capabilities, harmless args and authorization.
10. Browser-session/local-resource adapters are distinct families, not evidence that every website or local resource is a registered plugin. Browser session status cannot certify API account access. Dynamic imported/local families must expose per-component requirements rather than send requiredEnv values through chat.
11. Mobile native/MCP/imported Connect currently emits model-facing prose through askPromInChat/connectMessage. Replace applicable branches with canonical structured start/resume and shared owner actions; keep existing direct desktop/provider and hosted callback behavior.
12. Shared cancel/verify/disconnect routes and adapter cleanup exist, but uniform lifecycle is not proven. Separate cancel, disable exposure, disconnect token use, delete stored app config and remote revoke; only four native bridges expose remote revoke. Test late callback, cancelled/replaced attempts and restart explicitly.
13. Verification quality needs bounded addendum: custom HTTP GET accepts any status <500 (including 401/403), and OpenAI-compatible /models probe sets streaming/toolCalling true without proving them. Require honest transport/auth/capability outcomes. **No row was real-auth verified; no build, source edits or account changes performed.**

## Shared family boundaries (apply to each matrix row)

### native
Existing native OAuth app configuration/vault and provider consent; generic protected API-key request is not a native client-secret collection path. Pin app schema, scopes, callback and selected identity.

Desktop native setup; mobile has prose fallback rather than structured parity; channels require owner UI handoff

### api
Protected owner + secure transport + OS-protected storage; schema fields from installed descriptor; service/attempt/reference binding. Never send values through model args.

Owner desktop/trusted mobile protected UI; agent/channel sanitized owner handoff; actual parity not runtime-tested

### local
Host resource/path/process permissions and declared schema; no secret required unless server-specific fields contain credentials. No automatic arbitrary filesystem grant.

Runs on gateway host, not phone filesystem; desktop host picker/process prerequisites; mobile should offer honest handoff

### oauthSpecial
Existing provider consent/setup-token owner flow; never generic password/2FA entry; preserve specific storage and consent

Existing desktop/provider flow; mobile structured parity not established; owner handoff required

### mcp
OAuth user consent or explicit process/endpoint/env setup; allowlist scopes/destinations/commands; protected secrets must not become model text

Gateway host runs transports; hosted Robinhood explicitly desktop-required; mobile use supported popup or owner handoff
