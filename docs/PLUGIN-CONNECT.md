# Plugin connection entrypoints

Implementation branch: feat/plugin-connect-flow. Not deployed until reviewed/merged.

`connection_ops(action:"start", service:"x", kind:"connector")` and `POST /api/connection-attempts/start` share a metadata-only starter. Use canonical kind + ID when IDs overlap (connector:github, mcp_preset:github, integration:github). Starting does not approve authentication. Unknown/unsupported installed setup stays the selected identity and reports SETUP_UNAVAILABLE; it never becomes a different plugin.

Desktop native Connect and mobile generic Connect render a shared action controller instead of sending chat prose. Existing hosted MCP popup branches, imported plugin enable and provider-specific Models setup remain in place. Start/reopen returns the same active attempt; concurrent same-target starts coalesce. Channels/tools get an action card; only the protected owner route may approve.

Owner consent is required by `/api/connection-attempts/:id/connect`, using existing Electron one-shot/body-bound consent or trusted paired phone proof. Browser-only environments without proof or protected storage fail closed. Continue is progress, not consent. Model `approved` flags do not authorize the connection.

Native OAuth covers the nine existing native bridges plus X, Instagram, LinkedIn and TikTok. App credentials use the existing protected card and typed save routes. Attempt-bound native app schemas pin clientId/clientSecret to the selected connector and reject cancelled/expired/mismatched attempts. X uses existing PKCE, not browser cookies; verification performs a bounded `/2/users/me` read. Provider app registration/approval is still an external prerequisite. Loopback providers require the PC/browser handoff; no phone-local redirect is promised.

Cancel invalidates pending native/MCP OAuth and guards late token commits; it does not delete a prior grant. Disconnect clears local access; remote revocation is labelled unavailable where unsupported. Delete-app and stop-use remain separate existing lifecycle actions. Late adapter results cannot resurrect cancelled attempts.

Generic keys with no safe read remain stored/unverified. Custom HTTP authentication failures do not verify. Model listing does not prove streaming/tool calling. Nous uses its existing OpenAI-compatible localhost proxy; Hermes must already be running. Existing provider credentials/model choice are preserved on registration.

### Additional isolated OAuth acceptance test
Run `node scripts/test-plugin-connect-oauth-ui.cjs` after compilation and descriptor copying. It uses actual connection routes/controller, the native OAuth adapter and OAuthConnector implementation, HTTP PKCE token exchange against a loopback fake provider, temporary vault storage, fixed authenticated safe read, and persisted resume. Six cases run at desktop1440 and mobile390: success, consent denial, token HTTP429, missing required scope, safe-read HTTP403, and cancellation while token exchange is pending. Wrong-state and replay callbacks are rejected. Mobile explicitly hands loopback consent to a separate PC browser page; this is not a physical phone. Native owner proof is injected. No external account credentials are used. Optional `PLUGIN_PROOF_DIR` retains screenshots outside temporary fixture storage.

`node scripts/test-plugin-connect-electron.cjs` exercises the actual production owner-consent BrowserWindow/preload/IPC under isolated development Electron, plus Windows safeStorage and fresh-process ciphertext decryption. It tests negative consent paths without solving the human challenge. Gateway lock transport is injected. It does not certify a packaged app, positive human consent, a paired phone, or full product vault integration; those require separate acceptance evidence.

`node scripts/test-plugin-connect-families.cjs` uses real adapters/orchestration/stores with injected external hosts to check local/hosted MCP, plugin identity, browser sessions, local resources, compatible model endpoints and generic keys. It initially exposed three regressions: missing MCP command reached launch, explicit unknown provider could fall back to caller endpoint, and pending browser cancellation omitted its cleanup hook. The correction validates before launch, keeps qualified identities out of generic endpoint/research fallbacks, and invokes optional browser close on cancel (not cookie deletion). Host simulations do not certify real MCP transports or live provider login.

## Direct user setup repair (follow-up to #852)
Connect is a user-driven operation, not an assistant request. Desktop canonical OAuth and mobile plugin setup use the same styled controller. Installed key/native OAuth schemas open protected inputs immediately; metadata-only preparation never launches OAuth or grants approval. An owner-proved Save authorizes credential storage and the native save confirms continuation; generic continue cannot advance a prepared native flow before saving. The missing secure-input → OAuth transition is restored. Existing hosted MCP/provider/local specialist setup remains direct.

Unpaired devices are detected before creating an attempt or collecting input and receive Settings → Pairing instructions. Pairing/owner approval itself is unchanged; knowing the public URL is not ownership. The optional Ask Prom to verify button appears only after stored/registered/connected status, sends identity and a read-only request, never credentials, and never runs automatically. Stored remains distinct from verified.

Proof: test-plugin-quick-connect.cjs exercises X first-time schema/form/save/continue with real route/controller/orchestrator and synthetic owner/provider/save sink; test-plugin-connect-http-ui.cjs uses real vault binding for a synthetic key; OAuth lifecycle and family suites retain negative cases. Screenshots are isolated desktop/mobile viewports, not a physical-phone or real X certification. No real account connected by these tests.
